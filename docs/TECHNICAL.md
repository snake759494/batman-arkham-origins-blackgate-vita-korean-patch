# 기술 설명

## 아카이브 `ozzy.psp2arc`

표준 PSARC(zlib, 블록 64KB)입니다. 항목 0은 경로 목록(manifest)이고 항목은 13,342개입니다. 블록 크기 표의 `0`은 꽉 찬 64KB 블록을 뜻하지만, 크기가 0인 파일의 블록 번호도 `0`으로 남아 있어 실제 데이터 길이는 0입니다.

패치는 원본 데이터를 그대로 두고 바꾼 파일을 끝에 덧붙인 뒤 목차(TOC)만 고칩니다(`tools/psarc_patch.py`). 목차가 길어진 만큼 기존 항목의 오프셋을 모두 밀고, 바꾼 항목은 새 블록과 오프셋을 가리키게 합니다. 그래서 원본 파일 길이 제한이 없고 xdelta가 작습니다.

## 텍스트 `*.cloc`

```
"LOCL" 헤더(0x20 바이트, 0x1C = 레코드 수 u32 BE)
레코드 × N:  u32 구간 수, 구간마다 [varint 길이][UTF-8 문자열][8바이트 타이밍(float 2개)]
꼬리: u32 언어 수(2), u32 키 수, 언어마다 (키 레코드 번호, 문자열 레코드 번호) × 키 수
```

언어 0은 영어, 1은 일본어입니다. 키 레코드는 문자열 키 자체를 담은 레코드입니다. 한글판은 두 언어 표를 모두 한국어 레코드로 향하게 하고, 같은 문장은 레코드 하나로 합칩니다(`tools/locbuild.py`). 자막 구간의 타이밍 8바이트는 일본어 레코드 것을 그대로 씁니다. `credits_screen.cloc`, `example.cloc`은 구조가 달라 손대지 않았습니다.

## 글꼴 `*.cfon` + `*.ctxr`

`cfon`은 `FONT` 헤더(버전 11, 크기 float, 글리프 수), 글리프 레코드(20바이트: 부호 있는 1바이트 xoff·advance·yoff·높이 + u0·v0·u1·v1 정규화 float), ASCII 128칸 u16 색인 표, 2바이트 UTF-8 문자 표, 3바이트 UTF-8 문자 표(개수·u16 색인·개수·u32 문자, 코드 순 정렬)로 되어 있습니다. 한글은 3바이트 표에 들어갑니다.

`ctxr`은 0xC0 바이트 헤더 뒤 DXT5 텍스처입니다. 폭 4096, 높이 = 데이터 크기 / 4096이고, 4×4 블록 단위 Morton(Z-order) 스위즐이 y축 비트부터 섞입니다(`tools/ctxr.py`). 글자는 RGB에 흰 채움, 알파에 모양(일부 글꼴은 1픽셀 테두리 포함)을 담습니다. 선택된 메뉴 줄은 알파를 검게 칠해 반전 글자를 만들므로, 글꼴마다 원본 영문 글리프의 알파/채움 비율을 재서 테두리 유무를 그대로 따릅니다.

`tools/fontbuild.py`는 가나·한자 글리프 칸을 모두 비운 뒤, 그 칸들 안에 들어가는 가장 큰 균일 칸 크기를 골라 한글을 렌더하고, 바뀐 4×4 블록만 DXT5로 다시 인코딩합니다. 한글 메트릭은 한자 「漢」의 것을 바탕으로 글자 간격만 보정합니다.

## 확인 방법

Vita3K 0.2.1(Qt 프런트엔드, Vulkan)을 백그라운드 창으로 띄워 PostMessage로 키·터치를 보내고, Vita3K 자체 스크린샷 단축키로 화면을 받았습니다(`tools/emu.py`). 진행해야 열리는 화면(수사 사건 상세, 보스 컷신)은 해당 문장을 열려 있는 화면(아이템 설명, 갤러리 첫 영상)에 옮긴 시험 빌드로 표시를 확인했습니다.
